# ADR-0028: DAPT の学習データも分割・トークン化した状態でキャッシュし、隠すのは学習中に専用の乱数で行う

- Status: Accepted
- Date: 2026-10-18
- ADR-0027 の「学習データは NTCIR-1 から検証の文書 ID を除いた残りとして作る」と、学習データを
  キャッシュに置かない扱いを置き換える

## 背景

ADR-0027 では、検証・テストデータだけを隠した状態でキャッシュし、学習データは学習のたびに
NTCIR-1 から検証の文書 ID を除いて作っていた。検証データは固定して保存するのに、学習データは
保存しない作りで、学習データを作るための「検証の ID を除く」手順が初見では読み取れない。

また、学習データを隠す collator は全体の乱数を使っていた。`set_seed(42)` により同じコードでは
同じ位置が隠れるが、ほかの処理が乱数を 1 回でも多く引くと、以降の隠し方がすべてずれる。

## 決定

### 学習データも分割・トークン化した状態でキャッシュする

```
cache/dapt/<model_id>/data/
  train/  分割・トークン化した学習データ (文書 ID つき、隠していない)
  val/    隠す位置を固定した検証データ (文書 ID つき)
  test/   隠す位置を固定したテストデータ (文書 ID つき)
```

学習と検証は `split_validation` で一度に分け、両方を保存する。検証の文書 ID を除いて学習データを
作る手順はなくす。

### 学習データは学習中に隠し、collator に専用の乱数を持たせる

学習データは保存した状態では隠さず、学習中に `DataCollatorForLanguageModeling(seed=42)` で
隠す。エポックごとに隠す位置が変わる。

collator は自分専用の乱数を持つため、隠し方はバッチが来る順番とその中身だけで決まる。バッチの
順番は `Trainer` のシャッフルで決まり、これもシード 42 から決まる。

検証・テストデータは ADR-0027 のとおり、隠した状態で保存したものを使う。

## 理由

- 検証データを保存するなら、同じ分割から出る学習データも保存しておけば、分割を 1 か所で決められる
- 学習データのトークン化 (31.6 万件で約 3 分) が 2 回目から要らなくなる
- 専用の乱数にすると、乱数を使う処理をほかに足しても隠し方が変わらない

## 採らなかった案

- **学習データも隠した状態で 1 組だけ保存する**: 全エポックで同じ位置を隠すことになり、
  エポックごとに隠し方を変える学習と中身が変わる
- **隠し方を変えた学習データをエポック数だけ保存し、つなげて 1 周学習する**: 隠し方まで
  キャッシュで固定できるが、エポック数だけ保存が要る (1 組約 1.1 GB の見積もり)。専用の乱数で
  隠し方がほかの処理から切り離せれば足りる
- **学習データを保存せず、全体の乱数で隠す (ADR-0027)**: 上の「背景」のとおり

## 結果

- `exclude` (検証の文書 ID を除く関数) はなくなる
- `Trainer` のシャッフルの仕組みや transformers のバージョンが変われば、隠し方は変わる
