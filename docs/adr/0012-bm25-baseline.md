# ADR-0012: BM25 ベースラインは Transfer-1 の指定構成で再現する

- Status: Accepted
- Date: 2026-08-30

## 決定

BM25 ベースラインを独自実装せず、NTCIR-17 Transfer-1 の組織者が指定した
ツールチェーンと設定をそのまま用いて再現する。

```
検索       PyTerrier v0.9.2      pt.BatchRetrieve(indexref, wmodel="BM25")
トークナイズ SudachiPy v0.5.4 + sudachidict_core + SplitMode.A
           クエリ・文書の両方に同一のトークナイザを適用する
出力       各トピック上位 1,000 件
```

手順は組織者の `notebooks/experiment-transfer1-train.ipynb` に従う。

## 背景

当初「組織者が配布している BM25 の結果ファイル (`top1000.train.tsv`) を使う」
方針を検討したが、確認した結果**公開リポジトリには含まれていない**。

```
.gitignore:
  testcollections/**
  indexes/**
  runs/**
```

リポジトリで公開されているのは結果ではなく**生成手順**である。したがって
「配布物を使う」ではなく「指定構成で再現する」形になる。

## 理由

- **BM25 は実装差で数値が大きく動く。** パラメータ (k1, b)、正規化、そして
  日本語では特にトークナイザの選択が効く。自前で選ぶと、その選択を弁明する
  必要が生じ、Transfer-1 との比較も成立しなくなる
- ADR-0011 でプロトコルを揃えた以上、ベースラインも揃えなければ比較可能性が
  片肺になる
- 再ランキングを扱う場合、Transfer-1 の第 2 サブタスクは「BM25 上位 1,000 件を
  再ランクする」設定であり、同じ候補集合を再現できる

## 結果

- 依存に `python-terrier` と `sudachipy` / `sudachidict_core` が加わる。
  PyTerrier は JVM (Terrier) を必要とするため、環境構築の手間が増える
- バージョンを固定する。PyTerrier v0.9.2 / SudachiPy v0.5.4 は 2023 年時点の
  指定であり、最新版では挙動が変わりうる
- BM25 の役割は 2 つになる
  1. **密ベクトルとの比較対象**としてのベースライン。1999 年の学術抄録に対して
     語彙一致は強く、これを置かずに「良いベクトルが得られた」とは主張できない
  2. **パイプライン全体の健全性チェック。** BM25 のスコアが妥当な範囲に収まれば、
     文書読み込み・qrels 対応・指標計算が正しく組めていることの傍証になる。
     極端に低い値が出た場合はデータ側の事故を疑う
- 生成した上位 1,000 件は保存して再利用する。毎回インデックスを作り直さない
