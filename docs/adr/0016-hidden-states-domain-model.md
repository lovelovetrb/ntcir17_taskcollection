# ADR-0016: 隠れ状態を domain model とし、層の選択と次元の選択を独立させる

- Status: Accepted
- Date: 2026-08-31

## 決定

層ごとの隠れ状態を中心的なデータ構造として扱い、そこから層を絞る操作と次元を
絞る操作を、いずれも同じ構造を返す独立した操作として定義する。

- 層を絞っても次元は保たれ、次元を絞っても層は保たれる
- 両者は可換であり、適用順序によらず同じ結果になる
- 絞り込んだ後も、元のモデルにおける層番号と次元番号を保持する
- 層を結合してひとつのベクトルにする操作は、この構造を返さない終端の操作として
  区別する

層と次元の格子から任意のセルを選ぶ方式は採らない。

パッケージ名は `hidden_subspace` とする。

## 理由

### 層と次元を独立させる

次元の選択は全層に共通の次元番号に対して行われるため、「第 42 次元」という
単位が層をまたいで保たれる。これにより「この次元は層によらず有用か」という
問いが立てられる。

### 元の層番号と次元番号を保持する

本研究の目的はモデル内部の機序に関する示唆を得ることであり、選択の結果が
「128 次元」ではなく「第 42・117・305 次元」として読めなければ示唆にならない。
絞り込みのたびに添字を引き継ぐ必要がある。

### 層と次元の格子から選ぶ方式を採らない

関連研究
[layer-redundancy-detector#60](https://github.com/lovelovetrb/layer-redundancy-detector/issues/60)
で、層と次元の格子 (11 × 768 = 8,448 セル) から指標上位のセルを選ぶ方式が
検証されている。結果は以下のとおりで、**セルの選択が層の選択に退化した**。

| モデル | 上位 768 セルの層内訳 |
|---|---|
| cl-tohoku/bert-base-japanese-v3 | 層 11 が 751 個 (98%) |
| cl-nagoya/unsup-simcse-ja-base | 層 12 が 595 個 (78%) |

原因は指標のスケール差にある。

| | 開き |
|---|---|
| 層をまたいだ差 | 1.66 × 10⁴ 倍 |
| 同一層内の次元間の差 | 1.8 〜 6.0 倍 |

層の違いが次元の違いを 4 桁近く上回るため、格子から選べば順位が層でほぼ決まる。
スケールを層ごとに回収した場合は、今度は層内の散らばりが最も狭い層が排除された。
**スケールを残しても回収しても機能しなかった。**

層と次元を独立した軸として扱えば、次元の選択が層の選択に退化することは構造的に
起こらない。次元を絞っても全ての層が残るためである。

## 結果

- 層の組み合わせと次元の選択を、互いに交絡させずに評価できる
- 「(層, 次元) の組の中でどれが有用か」という問いは立てられない。必要になった
  場合は、この構造を返さない別種の操作として追加する
- 絞り込み操作が可換であることは、実装時に不変条件としてテストで固定する
