# ADR-0017: ベクトルの作り方は連結から始める

- Status: Accepted
- Date: 2026-08-31

## 決定

選んだ層と次元から検索ベクトルを作る方法として、**連結**のみを実装する。

平均、重み付き和、最大は差し替えられる形にしておくが、当面は実装しない。

この操作は層を絞る操作・次元を絞る操作とは区別する。前二者は「何を残すか」を
答えるだけで値に触れないため互いに可換だが（ADR-0016）、この操作は値そのものを
作るため可換ではなく、絞り込みの後にのみ適用できる。

## 理由

Phase 1 の問いは「次元の選び方によって検索性能が変わるか」である（ADR-0006）。
連結は選んだ層の次元をすべて保つため、次元数を変える手段になる。次元数を
増やしたときに性能が上がるかどうかは、次元選択に余地があるかを考える材料に
なる。

先行研究
[BERT Has More to Offer (Findings of EMNLP 2023)](https://aclanthology.org/2023.findings-emnlp.1030/)
は層とトークンの両方を平均しており、出力は層数によらず 768 次元で固定される。
本研究が連結を採ると次元数が層数に比例して変わるため、層の組み合わせの効果と
次元数の効果が分離できない。

ただし本研究には次元を絞る仕組みがあるため、**次元数を揃えた比較が可能**である。
たとえば 1536 次元は「2 層 × 768 次元」「4 層 × 384 次元」「8 層 × 192 次元」の
いずれでも到達でき、同じ次元数で層への配分だけを変えた比較ができる。これは
出力が 768 次元に固定される平均では立てられない問いである。

## 結果

- 層の組み合わせに関する数値は、先行研究と直接比較できない
- 次元数と性能の関係が、層の組み合わせと次元の選択の両方から観測できる
- 検索ベクトルの次元数が層数に比例するため、層を多く使う構成ほど検索の計算量が
  増える。全 13 層を連結すると 9,984 次元になる
