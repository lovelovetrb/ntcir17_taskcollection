# ADR-0027: NTCIR-1 の文書で tohoku-bert に MLM の追加事前学習を行い、主成分の除去の効果が保たれるかを見る

- Status: Accepted
- Date: 2026-10-17

## 背景

NTCIR-1 と NTCIR-2 のそれぞれで、文書の平均を引き上位の主成分を除くと nDCG@1000 が
上がった。NTCIR-2 にだけある文書 (`ntcir2-unique`) から平均と主成分を推定しても、
NTCIR-2 全体から推定したときと同じく上がる。

次の問いは、隠れ状態がドメインに寄ったあとも除去の効果が保たれるか、である。モデルを
NTCIR-1 の文書に寄せ、寄せる前と後で除去の効果を比べる。

## 決定

### 学習

`cl-tohoku/bert-base-japanese-v3` に、NTCIR-1 の文書だけを使って MLM の追加事前学習
(DAPT) を行う。クエリと qrels は使わない。まず tohoku-bert で結果を見て、ほかのモデル
(`cl-nagoya/unsup-simcse-ja-base` など) で同じ検証をするかはその後に決める。

学習のコードは tohoku-bert に限らず、MLM の head を付けて読み込める Transformer の
エンコーダーなら学習できるように作る。学習するモデルは yaml で指定する。

- 文書テキストは検索と同じ `document_text` (TITL + ABST、ADR-0011) で作る
- 512 トークンで切る (ADR-0004)
- 隠し方は `DataCollatorForLanguageModeling` の既定 (15% を選び、そのうち 80% を
  [MASK]、10% をランダムなトークン、10% をそのまま)
- `set_seed(42)` で乱数を固定する
- bf16 で学習する
- 学習を終えた最後のステップのモデルを検索に使う

| 設定 | 値 |
|---|---|
| エポック数 | 3 |
| バッチサイズ | 128 |
| 学習率 | 5e-5 |
| スケジュール | 総ステップの 6% を warmup、その後線形に下げる |

エポック数を増やすときは最初から学習し直す。学習率のスケジュールは総ステップ数から
決まるため、3 エポックで終えたモデルから続けても、最初から長く回したモデルとは同じに
ならない。

### データの分け方

| 役割 | データ | 件数 |
|---|---|---|
| 学習 | NTCIR-1 の文書の 95% | 約 31.6 万件 |
| 検証 | NTCIR-1 の文書の 5% | 約 1.7 万件 |
| テスト | `ntcir2-unique` から、学会発表 (`ntc2-j1g`) と科研費報告書 (`ntc2-j1k`) を同数ずつ | 検証と同じ件数 |

NTCIR-1 の文書はシード 42 でシャッフルしてから分ける。テストの抜き出しもシード 42 で行う。

### 評価

- 検証とテストは、隠す位置を学習の前に一度だけ決めて保存し、どの評価でも同じものを使う。
  隠すのは学習と同じ collator をシード 42 で 1 回通した結果とする。学習データは今までどおり
  毎回ランダムに隠す
- `eval_on_start=True` とし、学習前 (0 ステップ目) の値を DAPT 前の値とする
- 500 ステップごとに評価する
- 指標は次の 4 つ。正解率と top-5 正解率は `compute_metrics` で計算し、
  `preprocess_logits_for_metrics` で上位 5 個のトークンだけを残す

| 指標 | 中身 |
|---|---|
| 損失 | 隠した位置での交差エントロピーの平均 |
| パープレキシティ | exp(損失) |
| 正解率 | 確率が最も高いトークンが正解と一致した割合 |
| top-5 正解率 | 正解が上位 5 個の候補に入った割合 |

指標は wandb に記録し、ファイルには書かない。

### 置き場所

```
cache/dapt/<model_id>/
  data/
    val/    隠す位置を固定した検証データ (文書 ID つき)
    test/   隠す位置を固定したテストデータ (文書 ID つき)
  models/
    <wandb の run 名>/   モデル本体と wandb のファイル
```

`data/` がなければ作り、あれば読む。学習データは NTCIR-1 から検証の文書 ID を除いた
残りとして作る。

### 設定の置き場所

| 置き場所 | 中身 |
|---|---|
| yaml (`src/hidden_subspace/dapt/` の中) | 変える頻度が高いもの: 学習するモデル、エポック数、バッチサイズ、学習率、warmup の割合 |
| コードの固定値 | 変えると `data/` を作り直す必要があるもの: シード、検証の割合、隠す確率、系列長 |

コードの固定値を変えるときは `data/` を消してから作り直す。

### コードの置き場所

学習のコードと入口を `src/hidden_subspace/dapt/` に置く。学習は `Trainer` で回し、設定は
dataclass で定義する。データの作成、隠す位置の固定、指標の計算などはファイルを分ける。

使う GPU はコードで決めず、実行時の `CUDA_VISIBLE_DEVICES` で選ぶ。

### 検索での比べ方

DAPT 後のモデルでも、既存の基盤 (mean-pooling、除く本数 k は全部) で NTCIR-2 を全件
検索し、主成分の除去を適用する。DAPT の前後 × 除去の有無で比べる。

## 理由

### FT ではなく DAPT にする

- 問いは「ドメインに寄ったとき」であり、DAPT はラベルもタスクの損失も使わないため、
  変化の原因をドメインに絞れる
- 検索タスクの FT (クエリと文書の対で学習する) は、ドメインに加えてタスクの目的関数が
  隠れ状態を変える。除去の効果が変わっても、どちらのためかを分けられない
- 対照学習が隠れ状態に与える影響は、ADR-0003 のペア (tohoku-bert → unsup-simcse) で
  別に比べられる
- NTCIR-1 の正解つきトピックは 83 件しかない

NTCIR-17 Transfer-1 の参加チームと主催者のベースラインは、いずれも FT を行っており、
DAPT を使ったものはない。

| チーム | 学習 |
|---|---|
| KANDUH | DeBERTa-v2 を jMARCO と NTCIR-1 で bi-encoder / cross-encoder として学習 |
| KASYS | Contriever、ColBERT、SPLADE を MS MARCO と NTCIR-1 で対照学習 |
| ditlab | sentence-BERT を jMARCO と NTCIR-1 で 3 種類の損失で学習 |
| 主催者 | monoBERT (`[CLS]q[SEP]d[SEP]` の二値分類) をリランキング用に学習 |

### テストを `ntcir2-unique` から取る

NTCIR-2 の文書集合は NTCIR-1 の文書 (332,918 件) を含む (ADR-0026)。学習で見ていない
文書でも損失が下がるかを測るため、NTCIR-1 にない文書から取る。

学会発表 (116,177 件) と科研費報告書 (287,063 件) を同数ずつにするのは、件数の多い
科研費報告書に偏らないためである。2 つは分けずに 1 つのテストとして測る。

### 検証を 5% にする

検証は損失を測るためだけに使い、数千件あれば足りる。DAPT のデータは NTCIR-1 の文書
だけで、検証に回すほど学習に使える量が減る。

### 隠す位置を学習の前に固定する

隠す位置を選ぶ乱数は学習中に進むため、`set_seed(42)` で固定しても評価のたびに隠す位置が
変わる。`DataCollatorForLanguageModeling(seed=42)` を指定しても同じである。位置が変わると、
ステップごとに別の問題を解かせることになり、損失の推移を比べられない。

位置を「前から何トークン」のように機械的に決めないのは、文書テキストが TITL + ABST の
順で、前から隠すとタイトルばかりが隠れるためである。学習と同じ隠し方にすることで、
学習で下げた損失と評価の損失が同じものを測る。

### 0 ステップ目の評価を DAPT 前の値とする

`eval_on_start=True` は、学習ループに入る前に評価を 1 回走らせる (transformers 5.16.1 で
確認)。DAPT 前のモデルを別に評価する必要がない。

### 指標

Precision と Recall は使わない。分類先が語彙の全部 (32,768 種類) で、トークンごとに
出しても全体として意味のある値になりにくい。top-k の k を 5 にするのは、transformers の
`fill-mask` パイプラインが既定で返す候補数と同じで、「モデルが出す上位 5 語に正解が
あるか」として説明できるためである。

### 学習の設定

- warmup 6% は DAPT の原論文 (Gururangan et al., 2020) と同じ
- 検索には最後のステップのモデルを使う。検証の損失で選ぶと、どのモデルを選んだかが
  新たな要因になる

### 条件をキャッシュに書かない

モデルの学習の設定は wandb が run ごとに記録する。データの条件はコードの固定値に置き、
変えるときは必ずコードの変更として git に残る。分割は検証データに入れた文書 ID から
復元できる。

## 採らなかった案

- **検索タスクで FT する**: 上の「FT ではなく DAPT にする」のとおり
- **`[CLS]q[SEP]d[SEP]` の二値分類で学習する**: クエリと文書を対にして入力すると、
  文書のベクトルが組んだクエリごとに変わる。既存の基盤はクエリと文書を別々にエンコード
  して内積で比べ、主成分もクエリと無関係な文書ベクトルから求めるため、入力の形が合わない
- **two-tower (クエリと文書で重みを分ける)**: 既存の除去は、文書から求めた平均と主成分を
  クエリにも当てる (`removal.py`)。空間が 2 つに分かれると、その根拠がなくなる
- **検証を 2 割にする**: 損失を測るだけには多すぎ、学習に使える量が減る
- **テストに `ntcir2-unique` の全件 (約 40 万件) を使う**: 500 ステップごとの評価が、
  1 回で学習 1 エポックと同じ規模になる
- **DAPT 前のモデルを別に評価する**: 0 ステップ目の評価で足りる
- **シード・隠す確率・系列長を yaml に置く**: yaml を書き換えただけで `data/` が古くなり、
  それに気づく仕組みがない
- **条件と分割を json でキャッシュに置く**: 上の「条件をキャッシュに書かない」のとおり
- **指標をファイルに保存する**: wandb に記録する

## 結果

- DAPT はまず tohoku-bert で行う。ほかのモデルは yaml でモデルを変えれば同じコードで学習できる
- 主成分の向きの比較 (DAPT の前後、NTCIR-1 と NTCIR-2) は、DAPT 後に除去を適用した
  結果が出てから決める
