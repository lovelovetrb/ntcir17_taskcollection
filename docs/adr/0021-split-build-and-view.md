# ADR-0021: ビューアを結果ファイルの作成と表示に分け、表示側を軽い環境で動かす

- Status: Accepted
- Date: 2026-09-20

## 決定

層ごとの検索結果を読むビューア (ADR-0020) を、結果ファイルを作る側と表示する側に分ける。
ADR-0020 の「エントリポイントを 1 つにする」を置き換える。

```
作成   python -m layer_inspector.build
       記録・キャッシュ・GPU・トークナイザを使い、結果ファイルを書き出す

表示   streamlit run sandbox/layer_inspector/app.py
       結果ファイルだけを読む
```

表示側は `hidden_subspace`・`torch`・`transformers` のいずれも import しない。表示に使う型は
表示側に置き、結果ファイルからは表を描くのに要る値だけを読む。判定のラベル (A / B / C) も
表示側に持つ。

結果ファイルの形式は変えない。作成側は今までどおり、トピックの記録を実験の記録と同じ形で
書き出す。

依存は dependency group `viewer` に `streamlit` だけを入れる。表示側のコンテナは
`uv sync --only-group viewer --no-install-project` で環境を作り、結果ファイルと表示側の
コードだけを置く。

結果ファイルがない状態で表示を起動したときは、作成のコマンドを案内して止まる。

## 背景

ビューアを研究室の外の計算機から見られるようにして、共有できるようにしたい。

## 理由

### 表示に必要なのは結果ファイルだけである

表示に使うのは 197 KB の結果ファイルだけで、クエリと文書は decode 済みの文字列として
入っている。トークナイザを呼ぶのは結果ファイルを作るときだけである。

それでも今は、表示のために 5.3 GB の環境が要る。表示の入口が結果を作る処理を呼ぶため、
`torch` と `transformers` を読み込むからである。streamlit だけの環境は 364 MB で済む。

### 表示側から `hidden_subspace` を切り離す

`hidden_subspace` の型 (`TopicResult` など) 自体は標準ライブラリしか使わない。しかし表示側が
このパッケージを import すると、表示用の環境にもパッケージを入れることになり、その依存で
ある `torch` と `transformers` が入る。表示側が結果ファイルから値だけを読めば、パッケージを
入れずに済む。

### 結果ファイルの形式は変えない

表示側が自分の型に読み込むため、形式を変えなくても表示側は軽くなる。形式を変えると、
作成側の保存と読み戻しのテストも書き直しになる。

## 採用しなかったもの

- **エントリポイントを 1 つのままにする (ADR-0020)。** 表示の入口が結果を作る処理を持つ限り、
  表示だけの環境を作れない。結果ファイルがないまま起動したときの分かりにくさは、作成の
  コマンドを案内して止まることで補う
- **表示側でも `hidden_subspace` の型に復元する。** 型そのものは軽いが、パッケージを入れると
  依存の `torch` と `transformers` が付いてくる
- **結果ファイルを表示向けの形に作り直す。** 表示側が自分の型に読み込む以上、軽さのためには
  要らない。作成側のテストを書き直す手間だけが増える
- **Cloudflare Workers に載せる (stlite)。** 表示側を純粋な Python にすれば載せられるが、
  Workers の有料プランが要る。まずはコンテナで動かし、必要になったら改めて判断する

## 結果

- 作成は GPU のある計算機で行い、表示側のコンテナには結果ファイルを持たせる
- 結果ファイルには NTCIR の文書本文が入る。テストコレクションは利用許諾の対象であり、
  公開のレジストリや、認証のない URL に置かない
- 記録やキャッシュを作り直したときは、作成のコマンドを実行し直す
