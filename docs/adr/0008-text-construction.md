# ADR-0008: 文書テキストとクエリテキストの構成

- Status: **Superseded in part by [ADR-0011](0011-follow-transfer1-protocol.md)**
  （文書テキストは `TITL + ABST`、クエリは `TITLE` に変更。以下の本文は決定当時の
  記録として残す。フィールド選択の測定値と EUC-JP 等の実装上の注意は引き続き有効）
- Date: 2026-08-30

## 決定

### 文書テキスト

`mlir/ntc1-j1`（ADR-0009）の各 `<REC>` から、以下の 3 フィールドを**この順序**で、
半角空白 1 個で連結する。

```
TITL → ABST → KYWD
```

- `KYWD` 内の区切り文字 `//` は半角空白に置換する
- `ABST` 内の `<ABST.P>` 段落タグは除去し、段落は半角空白で連結する
- フィールドが欠損している場合はスキップする（区切りの空白も出さない）
- `[SEP]` 等の特殊トークンをフィールド間に挿入しない

その他のフィールド（`AUPK` 著者、`CONF` 会議名、`CNFD` 開催日、`SOCN` 学会名、
および `TITE` / `ABSE` / `KYWE` / `AUPE` / `SOCE` / `CNFE` の英語フィールド）は
使用しない。

### クエリテキスト

トピックの `<DESCRIPTION>` フィールド単独を使用する。

`TITLE` / `NARRATIVE` / `CONCEPT` / `FIELD` は使用しない。

## 理由

### フィールド選択（文書）

`TITL` / `ABST` / `KYWD` は文書の内容を表すフィールドである。著者名・会議名・
学会名は内容と無関係な固有名詞であり、密ベクトルでは意味的なノイズになる。
`ntc1-j1` は英語フィールドを持たないため、英語の使用可否は問題にならない
（ADR-0001 / ADR-0009）。

### 連結順序

ADR-0004 の 512 トークン truncate は末尾から効くため、順序に意味がある。
`cl-tohoku/bert-base-japanese-v3` のトークナイザで全 332,918 件を実測した結果:

```
トークン数(TITL+ABST+KYWD)  p50=209  p90=299  p99=573  p99.9=842  max=3,539
510 トークン超過            6,073 件 (1.82%)

フィールド別 平均トークン数  TITL 17.4 / ABST 188.9 / KYWD 13.0
フィールド欠損              TITL 0 / ABST 0 / KYWD 19,205
```

**truncate が発生するのは 1.82% のみ**であり、順序の選択は実質的にほぼ影響しない。
超過 6,073 件における損失の内訳:

| 順序 | TITL | ABST | KYWD |
|---|---|---|---|
| `TITL → KYWD → ABST` | 無傷 | 6,073 件で末尾切断 | 無傷 |
| `TITL → ABST → KYWD` (採用) | 無傷 | 5,332 件で切断 | 5,372 件で完全消失 |

損失最小は `TITL → KYWD → ABST` だが、採用案との差は「全体の 1.6% の文書が
平均 13 トークン（510 トークン中 2.5%）のキーワードを失う」のみである。
元レコードのフィールド順を保ち、タイトル直後に抄録が来る自然な語順を優先した。

`ABST` を先頭に置く案は、`ABST` が長い文書ほど `TITL` と `KYWD` の**両方**を
失うため採用しない。短く情報密度の高いフィールドを先頭に置くのが原則となる。

### クエリフィールド

全 83 トピックの実測:

```
DESCRIPTION  字数 min=7  p25=21  p50=28  p75=37  max=79
TITLE        字数 min=3          p50=8           max=21
NARRATIVE    字数 min=60         p50=260         max=637
```

- `MANUAL-E.PDF` 4.3 のトピック作成基準 (2) に
  **"`<Description>` contains every concept needed to describe the topic"**
  と明記されている。DESCRIPTION 単独でトピックを記述するのに必要な概念を
  すべて含むよう作られており、単独使用は一次資料に裏付けられた選択である
- 1 文の自然な検索要求であり、本研究が最終的に想定する RAG のクエリに最も
  近い粒度である
- `TITLE` は「ロボット」のような 1 語の名詞句が含まれ、埋め込みとしての情報量が
  不足する。層ごとの差を見る実験のノイズになる
- `NARRATIVE` は「〜は検索要求を満たさない」「〜は不可」といった**否定表現**を
  含む。密ベクトルは否定をほぼ表現できないため、情報量が増えても性能が
  悪化する可能性が高い
- `CONCEPT` は関連語の列挙であり、BM25 のような語彙一致には効くが密ベクトルでは
  冗長になりやすい

## 結果

- クエリは 83 件しかないため、後から別フィールドを試すコストはほぼゼロである。
  クエリ構成は必要なら実験軸として追加できる
- 文書テキストを変更する場合は全 338,064 件の再エンコードが必要になる
  （1 モデル約 1 時間、キャッシュ 6.8 GB）。安価ではあるが自明ではないため、
  文書構成は 1 つに固定して進める
- BM25 ベースラインにも**同一のテキスト構成**を用いること。テキストが違うと
  密ベクトルとの比較が成立しない
