# ADR-0037: 隠れ状態を z スコアに直し、文書のクラスタごとに選んだ (層, 次元) で文書ごとのベクトルを組み立てて検索する

- Status: Accepted
- Date: 2026-11-25
- ADR-0014 の「座標ごとの標準化は採用しない」を、この実験について置き換える

## 背景

pc_removal (ADR-0034・0035) で、次のことが分かった。

- FT 前のモデルでは、隠れ状態から主成分を除くと、生のモデルより検索の性能が少し上がる。上がるのは主に 0 層目である
- FT 後のモデル (DPR) に同じ操作をすると、性能は下がる
- 主成分を除いても、DPR による FT ほどには性能は上がらない

ドメインごとに FT するのはコストが大きい。FT せず、ラベルも使わずに、文書集合だけから検索用のベクトルを
組み立てる方法を、どの層・どの次元が効いたかを説明できる形で作りたい。ここでは、FT が各層の隠れ状態を
集約し直してドメインに合わせていると見て、文書ごとに使う隠れ状態を選ぶことで同じことに近づけるかを試す。

先行研究のうち、次の 2 つがこの実験に直接関わる。

- Timkey & van Schijndel (EMNLP 2021) は、文脈付き表現のコサイン類似度やユークリッド距離が 1〜5 個の
  次元 (rogue dimension) に支配され、表現の質が見えなくなっていることを示した。これらの次元は位置や
  句読点と強く相関する。次元ごとの標準化でこれを直すと、どの層でも表現の質が保たれていた
- Rajaee & Pilehvar (ACL 2021) は、文脈付き表現をクラスタに分け、クラスタごとに支配的な向きを除く。
  対象は単語の表現と STS・WiC で、再現研究 (NeurIPS 2022) では意味のタスクでの改善はまちまちだった

## 決定

### 対象

| 項目 | 値 |
|---|---|
| モデル | `cl-tohoku/bert-base-japanese-v3`、`FacebookAI/xlm-roberta-large` (どちらも FT 前) |
| コレクション | 引数で指定する。NTCIR-2 で回す。NTCIR-1 も同じ引数で回せる |
| プーリング | mean |
| 評価 | 既存の layer-sweep と同じ指標 |

### 標準化

文書のコーパスで、層ごと・次元ごとに平均 μ と標準偏差 σ を求め、z = (x − μ) / σ に直す。問いにも文書の
μ と σ を使う。

### 予備実験: z スコアの layer-sweep

既存の layer-sweep と同じ条件で、ベクトルを z スコアに直すことだけを変えて回し、生の layer-sweep と比べる。

標準化で生のモデルより上がるか、上がるならどの層かを見る。

### 基準値: z スコアの全層をつないだベクトル (k = 1)

クラスタに分けず、次元も選ばずに、z スコアに直した全層をつなぎ、コサイン類似度で検索する。これを
クラスタに分けない場合 (k = 1) とする。k = 1 では z の平均がどの次元でも 0 になり次元を選べないため、
全次元を使う。各次元の分散は 1 にそろっているので、層ごとの L2 正規化はかけない。

### 固まりの確認

層ごとに、z スコアに直した文書のベクトルで、k ごとのシルエット係数を出す。同じ次元数の標準正規分布の
乱数データ (z スコアと同じ平均 0・分散 1) での値と比べ、固まりがあるかを確かめる。

### クラスタリング

文書側で、層ごとに z スコアに直したベクトルに k-means をかける。k は 2, 4, 8, 16, 32 を振り、結果は
k ごとの曲線で出す。

### 問いの割り当て

層ごとに、問いの z スコアのベクトルを最も近いクラスタの中心に割り当てる。問いがクラスタにどう散らばるかを
数える。

### 次元の選び方

層 l・クラスタ c ごとに、クラスタ中心の座標の絶対値 (クラスタ内の z の平均の絶対値) の上位 m 個の次元を
選ぶ。m は、1 層の次元数 d (BERT 768、xlm-roberta-large 1,024) に対する割合 r で m = r × d とし、
r は 4%, 8%, 16%, 33% を振る。結果は r ごとの曲線で出す。

### ベクトルの組み立て

文書も問いも、層ごとに属するクラスタで選んだ次元だけを残して他を 0 にし、全層をつなぐ。

次元の選び方はクラスタごとに決まるが、違うクラスタで選ばれる次元が重なることも、一致することもある。
k = 2 では z の全体平均が 0 であることから n₁c₁ + n₂c₂ = 0 (n はクラスタの文書数、c はクラスタの中心) が
成り立ち、2 つのクラスタで選ばれる次元は必ず一致する。このため k = 2 は、2 つの群の差が大きい次元を
選び、全文書が同じ次元を使う条件になる。k を並べると次のようになる。

| k | 次元を選ぶか | 文書ごとに次元が違うか |
|---|---|---|
| 1 (基準値) | 選ばない (全次元) | 違わない |
| 2 | 選ぶ | 違わない |
| 3 以上 | 選ぶ | 違いうる |

k = 1 と 2 の差で次元を選ぶこと自体の効果を、k = 2 と 3 以上の差で文書ごとに選ぶ効果を見る。ただし、
k が変わると選ばれる次元も変わるため、2 つの効果は完全には切り分けられない。

### スコア

問いと文書の両方が残した次元だけでコサイン類似度をとる。共通の次元がない文書は最下位にする。
共通の次元の数ごとの正解率も見る。

## 理由

- **z スコアに直す**: 残差 (LayerNorm 後) の絶対値で次元を選ぶと、rogue dimension がどのクラスタでも上位に
  来る。z スコアに直すと、どの文書でも同じ値をとる次元は特別扱いされず、クラスタに固有のずれだけが残る
- **ADR-0014 の「座標ごとの標準化は採用しない」を置き換える**: ADR-0014 は、標準化が次元間のスケールの違いを
  消し、次元ごとの差を見る目的に反するとして採らなかった。Timkey & van Schijndel は、そのスケールの違いの
  大部分が、類似度を支配する一方でモデルの振る舞いをほとんど左右しない少数の次元から来ることを示した。
  この実験で見るのはスケールの違いではなく、クラスタごとのコーパスからのずれである
- **全層をつないだ基準値を置く**: 層を 1 つずつ使う layer-sweep だけを基準にすると、層をつないだ効果と
  次元を選んだ効果が混ざる
- **予備実験で z スコアの layer-sweep を回す**: 0 層目以外の層の情報が rogue dimension に隠されているのか、
  内積で測れる形になっていないのかを区別する。前者なら標準化で中間の層の性能が上がる
- **固まりを確かめる**: z スコアに直してもクラスタの構造があるとは限らない。構造のない乱数データと差が
  なければ、その層ではクラスタごとに選ぶ方式を使わない
- **層ごとにクラスタに分ける**: 層ごとに違う分かれ方が出るかを直接見られる。全層をつなぐと、隣どうしの
  似た層が距離を支配し、何で分かれたかを読めなくなる
- **k と r を振って曲線で出す**: どの手法にもクラスタ数か、それに代わるパラメータがある。正解ラベルで
  1 つに選ぶと評価に使う問いで調整したことになるため、値ごとの結果を出す
- **k-means**: HDBSCAN は 768〜1,024 次元ではそのままでは効きにくく、次元を落とすとパラメータが増える。
  階層的クラスタリングは切る距離のしきい値が k と同じ働きをする
- **クラスタ中心の座標の絶対値**: k-means の中心がそのまま使え、計算が増えない。絶対値をとるので、
  コーパスより小さい側にずれる次元も選ぶ
- **次元数を固定する**: しきい値で選ぶとクラスタごとに次元数が変わり、内積の大きさがそろわない。
  割合で決めると次元数の違う 2 つのモデルを並べられる
- **文書ごとに組み立てる**: FT が文書ごとに使う隠れ状態を変えていると見たときの、最も直接の操作である
- **問いを文書のクラスタの中心に割り当てる**: 文書側で作ったクラスタと次元の選び方を、そのまま問いに使える
- **共通の次元でのコサイン類似度**: 共通の次元の数が文書ごとに違っても値が −1〜1 にそろう。内積の合計
  では、同じクラスタの層が多い文書ほど点数が大きくなり、負の点数の文書が共通の次元のない文書 (点数 0) より
  下に来る
- **Rajaee & Pilehvar との違い**: あちらはクラスタごとに支配的な向きを除く。この実験はクラスタごとに
  次元を選び、文書ごとのベクトルを組み立てる

## 取らなかった方法と、結果によって取る条件

| 方法 | 取らなかった理由 | 取る条件 |
|---|---|---|
| FFN の中間層 (GELU の後、BERT 3,072 次元、xlm-roberta-large 4,096 次元) の活性化で選ぶ | 隠れ状態を取り直す必要があり、次元数が 4 倍になる。0 層目がない | 残差の z スコアで選んだ次元の意味が読めないとき。GELU が座標ごとにかかるので、次元ごとの解釈がしやすい |
| 全層をつないだベクトルでクラスタに分ける | 隣どうしの似た層が距離を支配する | 層ごとに分けた結果で、どの層にも固まりがないとき |
| HDBSCAN・階層的クラスタリング | 上の理由 | 性能が k に強く依存し、k をラベルなしで決められないとき |
| 次元をクラスタ内の z の平均 ÷ 標準偏差で選ぶ | 計算が一段増える | 選んだ次元が、少数の文書の極端な値で選ばれているとき |
| 問いは全次元を使い、文書だけ次元を絞る | クラスタの割り当てを問いにも使う方を取った | 問いがほぼ 1 つのクラスタに集まるとき |
| 共通の次元での内積の合計、または平均 | 上の理由 | コサイン類似度で、共通の次元が少ない文書が上位に偏るとき |
| 全クラスタで選んだ次元の和集合を全文書で使う | 文書ごとに次元を選ぶ要素がなくなる | 文書ごとの組み立てで基準値を超えないとき。次元を選ぶこと自体が効くかを切り分ける |

## 結果

- xlm-roberta-large の NTCIR-2 の mean のキャッシュと layer-sweep の記録はすでにある。BERT の NTCIR-2 の
  キャッシュもある。隠れ状態を取り直す必要はない
- シルエット係数は全件 (NTCIR-2 は 736,158 件) では計算量が大きい。標本の取り方は実装のときに決める
- コードの置き場所と記録の形は、実装の PR の前に決める
