# ADR-0004: 入力長は 512 トークン truncate で統一する

- Status: Accepted
- Date: 2026-08-30

## 決定

全モデル・全文書・全クエリで、512 トークンに truncate する。チャンク分割と
その集約は行わない。

## 理由

- 対象 2 モデルとも `max_position_embeddings = 512` であり、これを超える入力は
  そもそも扱えない
- NTCIR-1 (`mlir/ntc1-j1`, 332,918 件) の文書テキスト (TITL + ABST + KYWD) は
  短い。`cl-tohoku/bert-base-japanese-v3` のトークナイザで全件実測:

  ```
  トークン数  p50 = 209   p90 = 299   p99 = 573   p99.9 = 842   max = 3,539
  510 トークン超過 = 6,073 件 (1.82%)
  ```

  truncate が発生するのは 1.82% に留まり、Phase 1 では情報損失がほぼない
- チャンク集約方式を入れると、層・次元の効果と交絡する新たな実験軸になる

## 結果

- Phase 1 では長文処理は論点にならない
- Phase 2 で NTCIR-2 の kaken（科研費報告書）を扱う際は状況が変わる。kaken の
  抄録は複数段落で桁違いに長いため、その時点で再検討が必要になる
- 文書テキストを組み立てる際、truncate で落ちるのは末尾であるため、
  **フィールドの連結順序**が意味を持つ（別 ADR で決定する）
