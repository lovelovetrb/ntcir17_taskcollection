# ADR-0013: 報告する指標と k の値

- Status: Accepted
- Date: 2026-08-30

## 決定

以下を計算・報告する。

| 指標 | k | 位置づけ |
|---|---|---|
| **nDCG@k** | **1000**, 10, 1 | **主指標は nDCG@1000**（ADR-0011、Transfer-1 準拠） |
| Precision@k | 1000, 10, 1 | 補助指標 |
| Recall@k | 1000, 10, 1 | 補助指標 |

適合の判定は ADR-0011 に従い `rel >= 1` の 2 値（A と B を適合、C と未判定を非適合）。

Precision と Recall は Transfer-1 の公式プロトコルに含まれない本研究独自の補助指標
である。主指標が nDCG@1000 である限り、Transfer-1 との比較可能性は保たれる。

## 各指標の直感的な解釈

- **nDCG@k** — 上位 k 件のランキングが、そのトピックで達成可能な最良のランキングに
  どれだけ近いか。適合文書を上位に置くほど高くなる。
- **Precision@k** — 上位 k 件のうち、どれだけが当たりだったか。「返した結果に
  ハズレがどれだけ混ざっているか」を見る。
- **Recall@k** — そのトピックの適合文書のうち、上位 k 件でどれだけ拾えたか。
  「取りこぼしがどれだけあるか」を見る。

k による見え方の違い:

- **k=1** — 1 位に何を置けたか。「一発で当てられるか」。
- **k=10** — ユーザーが実際に目を通す範囲。RAG が文脈として詰め込む範囲にも近い。
- **k=1000** — 第 1 段階検索として、適合文書を候補集合に取り込めているか。
  再ランキングに渡す前段としての性能。

## 解釈してはいけない組み合わせ

`|R|`（そのトピックの適合文書数、A|B）は NTCIR-1 で min=5 / 中央=22 / max=1,539 と
470 倍の幅がある。このため上限が構造的に潰れる組み合わせが存在する。

| k | Precision@k の上限 | Recall@k の上限 | nDCG@k の上限 |
|---|---|---|---|
| 1 | 1.0（83/83 トピック） | 中央 **0.0455** / 最大 0.2 | 1.0（83/83） |
| 10 | 中央 1.0 / 最小 0.5（74/83 が 1.0） | 中央 0.4545（14/83 が 1.0） | 1.0（83/83） |
| 1000 | 中央 **0.0220**（1/83 が 1.0） | 中央 1.0（82/83 が 1.0） | 1.0（83/83） |

- **Precision@1000 を性能として解釈しない。** 上限の中央値が 0.022 であり、
  実質的に `|R| / 1000` を測っている。適合文書が 22 件のトピックで 1,000 件返せば、
  完璧に検索しても 0.022 が上限になる
- **Recall@1 を性能として解釈しない。** 同じ理由で上限の中央値が 0.0455

計算はする（コストがゼロであり、値を出さない理由がない）が、**この 2 つは
表に載せても比較には使わない**。

**nDCG はすべての k で上限が 1.0 に揃う。** IDCG がそのトピックで達成可能な最良値
だからである。これが nDCG@1000 を主指標に据えられる理由であり、Precision / Recall と
決定的に違う点である。

## Precision@k と Recall@k は同一トピック内では同じ情報である

```
P@k = (上位 k 件の適合数) / k
R@k = (上位 k 件の適合数) / |R|

分子が同じ  →  P@k = R@k × |R| / k
```

トピック単位で見れば「上位 k 件に適合が何件あったか」という 1 つの数を、`k` で割るか
`|R|` で割るかの違いでしかない。両者に差が出るのは**マクロ平均を取るとき**だけで、
トピックごとに `|R|` が異なるため重み付けが変わる。

したがって指針は次のようになる。

```
小さい k  →  k で割る Precision が意味を持つ
大きい k  →  |R| で割る Recall が意味を持つ
```

## k=1000 で未判定文書が混入することについて

NTCIR-1 では**全トピックで判定済み文書が 1,000 件を超えている**（最小 1,532 /
中央 2,519 / 最大 7,732）。したがってプール自体が k を下回ることはない。

ただし上位 1,000 件は全 332,918 件から選ばれるため、そのトピックの判定済み
（平均 3,147 件）と重なるのは一部に留まる。混入した未判定文書は ADR-0007 に従い
非適合 (gain 0) として数える。計算は破綻せず、指標の定義も well-defined である。

## 集計方法

マクロ平均（トピックごとに指標を計算してから 83 トピックで平均する）を用いる。
トピックごとの値も保存し、構成間の比較では対応のある検定を行えるようにする。

## 採用しなかったもの

- **MAP / MAP@k** — `MAP@k` には統一された定義がなく、分母を `min(|R|, k)` とするか
  `|R|` とするかで流儀が分かれる。一方、上位の質は nDCG@10 が、全体のランキング品質は
  nDCG@1000 が担うため、追加しても情報が重複する。必要になれば後から足せる
- **bpref / condensed list** — 未判定文書を評価から除外する手法であり、スコア順に
  並べるシステムにとってはプール内再ランキングと等価になる（ADR-0007）
- **graded nDCG（A=2, B=1 を利得として使う）** — ADR-0011 で Transfer-1 に合わせ、
  評価は `rel >= 1` の 2 値とした
